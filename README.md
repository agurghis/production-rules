# The rules I run production by

I build and run software for real clients with two AI sessions and written rules. These are the rules, and the job and report formats that go with them. Each rule is here because something happened on a live project.

- [`RULES.md`](RULES.md) · 36 rules, each with one line of why
- [`job-format.md`](job-format.md) · what a job has to say before any code is written
- [`report-format.md`](report-format.md) · done, proof, next

## How to use them

1. Copy `RULES.md` into your project and point your AI coding tool at it (in Claude Code, reference it from `CLAUDE.md`).
2. Open two sessions. One writes jobs in the job format and checks reports. One writes code and reports in the report format. Neither does the other's part.
3. Carry every job and every report between them yourself, and run every server command yourself.

Change the rules to fit your project. Delete the ones that don't apply. Add one each time something goes wrong.

## Where they come from

Eight live projects, built with AI as part of the process: a SaaS for car dealers, dealer websites, a course platform, a company site with a CRM, and others. Client work is anonymised. The technical events are real.

The method behind the first four rules is Chapter 01 of The Production Kit, free: https://alexgurghis.com/kit
